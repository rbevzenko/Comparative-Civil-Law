# Профиль издания

Профиль — место, где локализуется разница между книгами. Без него каждая новая книга превращается в отдельную разработку; с ним вторая книга той же линейки идёт по готовым правилам за минуту.

Профиль привязан не к издательству вообще, а к **цифровой линейке**: у одного издательства бывает несколько поколений вёрстки. Поэтому в `id` есть версия, и при несовпадении заводится `-v2`, а не правится существующий. Правка задним числом опаснее, чем кажется: `profile` записан в уже нарезанных карточках, и после правки он описывает не то, чем они сделаны.

## Структура

```yaml
id: de-at-margin-v1
publisher: Verlag Österreich
jurisdiction: AT
language: de

units:                      # рядов может быть несколько
  - type: "Rz"              # как единица называется в традиции
    id_prefix: "rz"         # войдёт в external_id
    mode: margin            # flow | margin | heading
  - type: "Fall"
    id_prefix: "fall"
    mode: flow
    pattern: '^Fall\s+(\d{1,3})\b'      # группа 1 — номер
    use_section: false                   # задачи вне параграфов
    address_template: "Fall {number}"

margin:                     # только для mode: margin
  side: outer               # left | right | outer | inner | both
  parity: printed           # чем считать сторону разворота: printed | pdf
  scope: page               # где мерить полосу набора: page (по умолчанию) | book
  pad: 2.0                  # зазор между полосой и полем, pt
  side_hint: null           # ограничить поиск колонки одной стороной (scope: book)
  x_range: null             # [x0, x1] — ручное задание, если автопоиск не справился

address:
  section:
    mode: pattern           # pattern | outline | none
    pattern: '^§+\s*(\d+[a-z]?)\.'
    anchor: start           # start | anywhere
    min_size: null          # брать образец только со строк не мельче кегля:
                            # заголовок параграфа набран крупнее тела, и это
                            # единственное, чем он отличается от ссылки
                            # «§ 823 Abs. 2 BGB …» в начале строки
    outline_pattern: '§\s*(\d+[a-z]?)'   # если mode: outline
  template: "§ {section} {unit_type} {number}"

footnotes:
  mode: font_bottom         # font_bottom | position_bottom | links | endnotes | none
  body_size: 10.0
  note_size_max: 8.0
  bottom_band: 0.70         # доля высоты полосы, ниже которой начинается зона сносок

junk:
  patterns:
    - 'international\.scholarvox\.com'

statutory:
  patterns: [ '§+\s*\d+[a-z]?\s*ABGB' ]

cross_refs:
  patterns: [ '(?:oben|unten)\s+Rz\s*\d+' ]

citation:
  template: "{authors}, {title}, {edition}, {publisher}, {year}, {address}"
```

Доступные подстановки в шаблонах: `{authors} {title} {edition} {publisher} {year} {address} {unit_type} {number} {section} {page} {hierarchy}`.

## Как собирается новый профиль

Всё берётся из паспорта, который выдал `diagnose.py`. Ничего не берётся из головы.

**`units[].mode`.** Что показывает паспорт:

- есть таблица «Маргинальные номера» с сотнями попаданий и высокой монотонностью → `margin`;
- сработал паттерн в начале строк с монотонностью выше ~90% → `flow`;
- не сработало ничего, но есть внятные заголовки → `heading`, и об этом надо сказать человеку отдельно.

**`units[].pattern`** (для `flow` и `heading`). Брать кандидата с наибольшей монотонностью, а не с наибольшим числом срабатываний: паттерн с монотонностью 67% и тысячей попаданий хуже, чем с 99% и тремя сотнями — первый ловит посторонние числа. Проверить руками на трёх-четырёх страницах в разных местах книги.

Опора на контекст справа обязательна. Голое `^(\d+)` поймает колонцифры, годы, номера статей и номера сносок. У французов после номера идёт заглавная буква подзаголовка, у немцев — тоже; это и используется.

**`margin.parity`.** Если препринт книги нечётной длины, recto приходится на чётную страницу файла, и поля «переворачиваются». `printed` считает сторону по типографской колонцифре — это верно всегда, когда колонцифра читается.

**`margin.scope`.** По умолчанию `page`: полоса набора меряется на каждой странице. На книжном скане она гуляет на десятки пунктов, и общий на книгу коридор либо режет номера, либо залезает в текст. `book` — для ровных издательских файлов, и там он не роскошь, а необходимость: на первой странице каждого раздела текст закона набран с отступом, постраничная медиана уезжает, и цифры самого закона («1.», «2.», «3.» перечисления) садятся туда, где постранично ожидается поле. Получаются карточки из текста закона, а не из комментария.

**`margin.side`.** Из паспорта: доля чётных страниц около 100% или около 0% означает, что поле меняет сторону на развороте, и это `outer` либо `inner`, а не фиксированная сторона. Ровно половина — поле с одной стороны всегда.

Колонка ищется автоматически как вертикальный коридор, где почти нет буквенного текста, но регулярно стоят одинокие числа. `x_range` задаётся руками только тогда, когда автопоиск не справился (обычно из-за врезок или иллюстраций в поле) — и это решение записывается в журнал.

**`address.section`.** Нужен там, где номер единицы перезапускается внутри раздела. `pattern` — если заголовок параграфа стоит в тексте отдельной строкой; `outline` — если номера параграфов надёжно сидят в оглавлении файла; `none` — если традиция составного адреса не знает (французы, англичане).

**`footnotes.mode`.**

- `links` — в паспорте ненулевое «с адресом назначения». Лучший случай: связь берётся из файла. **Режим объявлен, но пока не реализован**; см. бэклог.
- `font_bottom` — сноски мелким кеглем внизу полосы (ветка A).
- `position_bottom` — только по положению (ветка B и файлы, где кегль не различается).
- `endnotes` — концевые, блок в конце главы или книги.
- `none` — сносок нет.

**`footnotes.body_size` и `note_size_max`.** Из гистограммы кеглей: первый — самый частый, второй — верхняя граница кандидатов. Между ними должен быть зазор минимум 1,5 pt, иначе разделение ненадёжно, и это надо сказать человеку.

**Знак сноски — конвенция издательства, а не константа.** Пайплайн читает «29)» и «29.»; часть издательств ставит голое число («29 Dazu näher …»). Тогда ни один знак не читается и вся полоса сносок страницы ложится одним блоком без номера — в отчёте это строка «Блоков сносок без читаемых номеров», и если она сравнима с числом страниц, дело именно в этом. При загрузке такие сноски отсеиваются: у приёмника номер обязателен и целочисленный.

Голое число само по себе слишком слабый признак — немецкие и австрийские сноски набиты номерами дел вида «5 Ob 142/68», начинающими строку так же. Рабочее правило — монотонность: номер принимается, только если он больше предыдущего принятого на этой же странице.

**`junk.patterns`.** Из раздела «повторяющийся мусор»: водяные знаки DRM и колонтитулы. Колонцифры скрипт снимает сам.

Сюда же — собственное оглавление раздела (Inhaltsübersicht у немцев и австрийцев). Его строки полны отточия, а справа стоит номер единицы, и этот номер садится ровно в коридор маргиналий: визуально он там и стоит. Каждый раздел тогда получает дубли своих же первых номеров. Отличить по положению или кеглю нельзя, а по отточию — безошибочно: `'\.\s?\.\s?\.\s?\.\s?\.'`. Проверить, что пяти точек подряд в прозе книги не бывает; многоточие из трёх под паттерн не попадает.

**`statutory.patterns`.** По юрисдикции, см. `citation-modes.md`. Проверить на выборке, что регулярка не съедает соседний текст: жадные конструкции в перечислениях статей — типичная ошибка.

## Проверка перед повторным использованием

Прогнать `diagnose.py` на новой книге и сверить: кегль тела, кегль сносок, паттерн или колонка маргиналий и их показатели. Разошлось хотя бы одно — новая линейка, новый профиль.

Соблазн подогнать существующий профиль «чуть-чуть» стоит дороже, чем выглядит: он ломает уже нарезанные по нему книги и лишает регрессию точки опоры.
